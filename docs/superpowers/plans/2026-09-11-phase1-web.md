# Phase 1 Web Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build the React client for the Phase 1 hotel guest-engagement platform — login, shared inbox, work-order board, analytics, notifications, admin CRUD and the phone simulator — against the already-shipped Flask API, reproducing the approved "Night Shift" mockups.

**Architecture:** Vite + React 18 + TypeScript (strict) + Tailwind, talking to the existing server over `/api` with a cookie session. Server state lives **only** in TanStack Query; UI state lives in components and two small contexts (session, theme). One `useRealtime()` hook owns the single native `WebSocket`, reconnects with backoff, and invalidates queries by event type — no component opens a socket. Types are generated from the server's committed JSON Schema, never hand-written.

**Tech Stack:** Vite 5 · React 18 · TypeScript strict · Tailwind CSS 3 · TanStack Query v5 · React Router v6 · Vitest + Testing Library · Playwright · json-schema-to-typescript

**Spec:** `docs/superpowers/specs/2026-09-10-hotel-engagement-phase1-design.md` — §5 defines every screen and behaviour; §4.7 the API; §4.8 type generation; §7 the required tests. Read it; this plan argues from it.

**Server:** complete and on `main` (247 tests green). API reference: `web/src/api/schema.json` (68 models) and `server/app/api/*.py`. Seeded logins are in `README.md`; all passwords are `Password123!`.

## Global Constraints

- **Node 20+ and npm.** All web commands run from `web/`. The repo root `package.json` already reserves the script names `web`, `dev` and `gen:types`.
- **TypeScript `strict: true`.** No `any` in committed code; no `@ts-ignore` without a comment naming the reason.
- **Types are generated, never hand-written.** `npm run gen:types` reads `src/api/schema.json` (a copy step from `server`'s committed export) and writes `src/api/types.generated.ts`. Both are committed. A test fails if the generated file is stale.
- **Wire format is camelCase.** The server already emits camelCase; do not transform casing in the client.
- **Server state only in TanStack Query.** No Redux, no Zustand, no server data in React state or context. UI-only state (open menus, draft text, selected tab) lives in components.
- **Exactly one WebSocket** for the whole app, owned by `useRealtime()`. Components read from it; they never construct one.
- **Error body shape is `{"error": {"code", "message", "details"?}}`.** The API client unwraps it into a typed `ApiError`; screens render `error.message`.
- **Auth is a cookie (`sid`, HttpOnly).** The client cannot read it. Session state comes from `GET /api/auth/me`. Never store credentials or tokens in `localStorage`.
- **Theme tokens are the mockups' values verbatim** (Task 1 lists both palettes). Dark is the default; light is a per-user toggle persisted server-side in `notification_prefs.theme`, falling back to `prefers-color-scheme`.
- **Status colours are reserved:** green = ok, amber = warn/accent, red = danger. Never decorative.
- **Fonts:** Space Grotesk (UI), JetBrains Mono (room numbers, timers, ids, counts), both with system fallbacks.
- **No component library and no charting library.** `src/components/ui/` holds ~8 small primitives; bars are CSS.
- **`/sim` is excluded from the production build.**
- Commit after every task with the message given. Never commit `node_modules/`, `dist/`, or `.env`.
